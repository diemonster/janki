# Tamaoka kanji database POC — 2026-09-07

Acquisition from the public Tamaoka export succeeded: the lookup form and the
server-generated CSV export both returned data, and the exact response bytes are
retained here. The source data **as retrieved** is nonetheless unsuitable for
individual-reading percentages or for ranking readings. Nothing in the runtime or
in Anki card behavior changed as a result of this POC. The Janki Assistant kanji
wizard remains a design proposal in [`docs/CARD_TYPES_PROPOSAL.md`](../../../../docs/CARD_TYPES_PROPOSAL.md);
it is not this POC.

Files: [`export.csv`](export.csv) (raw export), [`manifest.json`](manifest.json),
[`export-request.json`](export-request.json), [`jukugo-ri.csv`](jukugo-ri.csv),
[`jukugo-ri-request.json`](jukugo-ri-request.json).

License: the source snapshot and this derived report are CC BY-NC-SA 4.0. Attribute
using the exact authors and title recorded in `manifest.json`. Dataset scope is the
Mainichi newspaper 2000–2010; individual reading fields cover two-kanji compounds,
proper nouns excluded. The
[published method](https://tamaoka.org/scholarly/sadokuari/2017/154.pdf)
(printed pp. 703–705) describes these fields as per-reading occurrence counts. See the
[source homepage and license](https://www.kanjidatabase.com/).

## What the numbers show

Per-reading slot values do not reconcile with the accumulated-productivity columns for
the same kanji. The ratio between the two differs substantially from row to row —
including 鳥, whose reading sums are close to the same magnitude as its accumulated
columns — so the raw values cannot be read as percent observations of anything in the
export.

| Kanji | Σ reading slots L/R | Acc. Freq. Left/Right Prod. |
| --- | --- | --- |
| 物 | 60 / 113 | 130487 / 58706 |
| 特 | 162 / 4 | 4627 / 162626 |
| 鳥 | 656 / 490 | 5981 / 2068 |
| 料 | 39 / 99 | 99543 / 39271 |
| 理 | 163 / 205 | 205212 / 163378 |
| 生 | 889 / 366 | 235100 / 202970 |
| 行 | 934 / 385 | 282743 / 135777 |

An independent Jukugo lookup for 理 ([`jukugo-ri.csv`](jukugo-ri.csv)) returns 24
left-position compounds totaling 163378 and 53 right-position compounds totaling
205212. The kanji row reports the opposite assignment (Left 205212, Right 163378), so
the accumulated columns are reversed relative to the words themselves. The reading
values 163/205 are far smaller than either. The cause is unknown. A dropped thousands
suffix is one appearance-based hypothesis only; no source numbers were repaired here.

The exported numeric values also contradict the documented frequency ordering of the
slots: 鳥 has `Left1freq` 1 followed by `Left2freq` 655. Because the counts themselves
remain unverified, this does not establish whether the intended slot order is wrong.
Source labels are kept untranslated (`buQ`, `tyoo`, `zyoo`, `dori`, …); no kana was
inferred and no variants merged.

The original 2nd/3rd/4th edition XLS releases were checked and contain no individual
reading occurrence counts — only aggregate on/kun figures over a different corpus
scope — so they cannot repair the current source. See the
[author download page](https://tamaoka.org/en/download/index.html).

## Reproducing

From the repo root, `python3 scripts/tamaoka_poc.py` runs offline against the pinned
snapshot and emits JSON diagnostics: preserved labels and slot positions, the reading
sums, match results against the accumulated columns, `frequency_status` of
`unverified`, and `usage_percentages` of `null`. `--csv PATH` runs the same analysis on
an alternate local file. `--fetch /tmp/tamaoka-new.csv` retrieves a current response
into a **new** file (the path must not exist); it posts the exact saved
export-request to the official CSV export endpoint, has no runtime integration, and
never overwrites the canonical snapshot. `jukugo-ri-request.json` is the exact POST
payload sent to that same export URL for the independent Jukugo fetch and is retained
as evidence.

The hashes in `manifest.json` pin the source files. Diagnostic output generated by the
script is not an additional authoritative source.

## What a future POC would need

Corrected, authentic per-reading counts with a declared denominator, with corpus
labels and slot positions retained as issued and no Japanese-language interpretation
layered on top. Until that exists, do not use this Tamaoka snapshot to sort readings
for learners.
